# Development Log: FastAPI Tutorial Builder Frontend

This file logs all changes made, the rationale behind design decisions, the system's inner workings, and any bugs encountered during the implementation of the FastAPI web application.

---

## 1. Project Overview & Requirements

The goal is to build a web frontend that allows users to interact with the repository tutorial generator.
Key features:
1. **GitHub Repository Input**: A text input to paste repository URLs.
2. **Interactive Generation Button**: An arrow button to submit.
3. **Simulated Progress Visuals**: Animated step-by-step loading phase mimicking the backend flow node execution.
4. **Interactive Document Reader**:
    * Left sidebar listing all chapters.
    * Main panel rendering markdown files beautifully.
    * Dynamic execution of Mermaid diagrams.
    * Syntax highlighting for code blocks.
5. **FastAPI Backend**: Serving the static files and parsing markdown chapters from `output/sample-project` to mock the output.

## 3. How It Works (Technical Overview)

1.  **Request Flow**:
    *   User inputs a URL and clicks the Submit arrow.
    *   Frontend triggers the loading screen and initiates a `POST` request to `/api/generate`.
    *   Simultaneously, the frontend steps through simulated loading states ("Fetching Repository", "Identifying Abstractions", etc.) to match the expected execution time.
2.  **Mock Processing**:
    *   The backend scans `output/sample-project`.
    *   It reads `index.md` and maps its contents.
    *   It reads all matching `.md` chapter files, extracts their headers/filenames, and loads their full contents.
    *   Returns a payload:
        ```json
        {
          "success": true,
          "project_name": "sample-project",
          "index_content": "...",
          "chapters": [
             { "title": "Application Flow", "filename": "01_application_flow_.md", "content": "..." },
             ...
          ]
        }
        ```
3.  **Rendering Engine**:
    *   `marked.js` compiles the markdown text to HTML.
    *   `Prism.highlightAllUnder()` highlights all code snippets.
    *   `mermaid.run()` detects the generated flowchart definition and compiles it into a beautiful vector graphic.

## 4. Bugs Encountered & Solutions

1. **PowerShell double-quote escaping when testing endpoint**:
   * *Problem*: Running `curl.exe -d "{\"repo_url\":\"...\"}"` from PowerShell failed with `JSON decode error: Expecting property name enclosed in double quotes`.
   * *Solution*: PowerShell parses double quotes differently. Tested successfully using `Invoke-RestMethod` with single-quoted JSON bodies: `Invoke-RestMethod -Body '{"repo_url":"..."}'`.
2. **Special characters in pre-generated content**:
   * *Problem*: In some of the chapters (e.g. `03_product_catalog_.md` and `04_shopping_cart_.md`), some currency characters render as `?1` due to encoding discrepancies in the source `.md` files.
   * *Solution*: This is an issue in the pre-existing source `.md` files, not the server or frontend. Documented as a data encoding anomaly.
3. **ReferenceError: delay is not defined**:
   * *Problem*: The `delay(ms)` helper function was missing in `static/js/app.js` but was called by the cinematic loading steps function (`runLoadingSteps`).
   * *Solution*: Implemented the Promise-based `delay` helper function at the bottom of the script.

## 5. User-Side Setup & Configuration

To run this application with MongoDB connectivity and authentication, please configure the following settings on your machine:

1.  **Start MongoDB Locally or Remotely**:
    *   Make sure MongoDB is running locally at `mongodb://localhost:27017` (default).
    *   Or, if using MongoDB Atlas, copy your connection string.
2.  **Update Environment Variables**:
    *   Open your project `.env` file and append:
        ```bash
        MONGODB_URI=mongodb://your_mongodb_connection_string
        MONGODB_DB=codebase_tutorial_builder
        ```
    *   *(Note: If `MONGODB_URI` is not defined or MongoDB is not running, the application will print a warning on startup and automatically fall back to an in-memory dictionary database mockup so you can test all features without database setup!)*
3.  **Authentication & Accounts**:
    *   Upon first launch, you will be presented with a centered Login/Signup card.
    *   Click **Sign Up** to register a new user account.
    *   Passwords are encrypted using `bcrypt` before being stored in the database.
4.  **React Development & Production Build**:
    *   The React source code resides in the `frontend/` folder.
    *   To start the Vite React development server:
        ```bash
        cd frontend
        npm run dev
        ```
    *   To compile the React source code for production:
        ```bash
        cd frontend
        npm run build
        ```
        *(This compiles the React application and places the output directly into the FastAPI `static/` directory so they are served by the python server).*
